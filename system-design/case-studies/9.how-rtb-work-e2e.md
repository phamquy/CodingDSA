# How RTB Works (End-to-End)

Real-Time Bidding (RTB) is the process of selling a *single* ad impression via an automated auction, in real time, while a page/app is loading (typically within ~100–300ms end-to-end).

This doc describes the standard RTB flow, what each system does, what data moves between them, and where measurement + billing happen.

---

## 1) Who’s involved (key actors)

- **User**: loads a webpage or opens an app screen containing an ad slot.
- **Publisher**: owns the site/app and the ad inventory.
- **Publisher ad server** (e.g., GAM or similar): applies prioritization rules (direct campaigns vs programmatic) and serves the final creative.
- **SSP (Supply-Side Platform)**: represents publisher inventory in programmatic markets; constructs bid requests and enforces publisher controls.
- **Exchange**: the auction venue; sometimes integrated into the SSP.
- **DSP (Demand-Side Platform)**: represents advertisers; decides whether to bid and selects creative + price.
- **Advertiser / Agency**: defines budget, targeting, creatives, and goals.
- **Measurement / verification vendors** (optional): viewability, IVT/fraud detection, brand safety.
- **Identity & consent frameworks** (optional but common): handle user consent strings and IDs.

---

## 2) What’s being sold

- One **impression opportunity** for a specific **ad slot** (banner/video/native) on a page/app.
- The “product” includes context and constraints:
  - slot size/format
  - placement type
  - content/site/app signals
  - device and (coarse) location
  - policies: blocked categories, allowed creatives, floor price, deal eligibility

---

## 3) Core RTB flow (web/app, open auction)

### Step A — User triggers an ad opportunity
1. User loads a page or app screen.
2. The page/app triggers an **ad request** for an ad slot.

### Step B — Publisher decision: direct vs programmatic
3. The **publisher ad server** checks prioritization rules, e.g.:
	- guaranteed/direct
	- preferred deals / PMP
	- open auction RTB
	- house ads / passback
4. If programmatic is eligible, the opportunity is routed to one or more **SSPs/exchanges**.

### Step C — SSP builds the bid request (often OpenRTB)
5. The **SSP** constructs a **bid request** describing the impression and constraints.

Common fields (conceptually):
- **imp**: format (banner/video/native), sizes, placement hints, floors, deals
- **site/app**: domain/app bundle, page/category/content signals
- **device**: user agent, OS, screen, IP (often for geo), connection type
- **user**: IDs/segments when permitted + consented
- **regs / consent**: consent string and regulatory flags (GDPR/TCF, US state signals, etc.)

### Step D — Exchange fans out to DSPs
6. The exchange/SSP sends the bid request to many DSPs.
7. DSPs must respond within a tight timeout (tens of milliseconds).

### Step E — DSP decisioning (should-bid + how-much + which-creative)
8. Each DSP quickly evaluates:
	- eligibility (targeting, frequency caps, brand safety, creative rules)
	- expected value (pCTR/pCVR/LTV models)
	- budget/pacing constraints
	- selection of an eligible creative
9. DSP returns a **bid response**:
	- bid price (CPM)
	- creative markup or creative ID
	- metadata (advertiser domain/category, campaign IDs, tracking URLs)

### Step F — Auction and winner selection
10. The exchange runs the auction among bids that returned in time:
	 - filters invalid/blocked creatives
	 - enforces floors and deal rules
	 - selects winner

Auction types you’ll hear about:
- **First-price** (common today): winner pays what they bid.
- **Second-price** (historical / sometimes in specific contexts): winner pays slightly above the second-highest bid.

### Step G — Ad markup returned and rendered
11. The exchange returns the winning creative (or a reference) to the publisher path.
12. The browser/app loads and displays the creative.

---

## 4) What happens after serving (measurement + optimization)

### Impression / click / viewability tracking
- **Impression**: often counted when the ad is served (and/or when viewable, depending on definition).
- **Click**: user clicks and a click tracker fires.
- **Viewability**: measured by SDK/JS + vendors; important for pricing and quality.

### Conversions and attribution
- If a user later converts, the advertiser logs a conversion.
- Attribution determines which impressions/clicks get credit (last-click, multi-touch, data-driven), subject to privacy constraints.

### Feedback loop
- DSPs and platforms ingest logs (bid, win, loss, impression, click, conversion).
- Models and pacing update continuously (bid shading, frequency, budget pacing, creative rotation).

---

## 5) Money flow (high level)

Typical settlement chain:
- Advertiser pays DSP (media cost + fees)
- DSP pays exchange/SSP (clearing price)
- SSP pays publisher (net of SSP fees)

Reconciliation is based on win/impression logs; discrepancies are handled via reporting/adjustments (including invalid traffic filtering).

---

## 6) Common variants you should know

### Header bidding (web)
- The page runs an auction across multiple SSPs **before** (or alongside) the publisher ad server decision.
- The best bids are passed to the ad server so programmatic can compete fairly with direct campaigns.

### PMP / Deals (private marketplaces)
- Same RTB mechanics, but restricted buyers and negotiated terms.
- Implemented via **deal IDs** and special auction rules/floors.

### App (mobile) specifics
- Instead of third-party cookies, identity often relies on consented device identifiers (or privacy-preserving frameworks).
- Auctions still follow the same “bid request → bid response → render” pattern.

---

## 7) Timing mental model (why RTB is hard)

Within a single page/app load, you typically need:
- network round trips (publisher → SSP/exchange → DSP and back)
- DSP decisioning (models + constraints)
- creative retrieval/rendering

That’s why RTB systems emphasize: low latency, high availability, aggressive caching, strict timeouts, and robust fallbacks.

---

## 8) Interview-ready one-liner

RTB is: **“Describe an impression → solicit bids → run an auction → render the winning ad → measure outcomes → reconcile & optimize.”**
